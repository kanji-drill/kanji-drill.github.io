# 大学受験向け 漢字練習アプリ（共通テスト型）— 計画（レビュー 4 体反映版）

## Context
- 目的: 受験生が自習で使う漢字練習の PWA。センター試験・共通テスト型の「同音異字の選択式」で出題する。
- きっかけ: 生成AIに毎回問題を作らせたところ、3回目あたりから漢字が重複した。原因は、AI が過去の出題を覚えていないこと。
- 方針: 出題する語は管理された語彙マスタから選び、出題履歴はアプリが記録する。重複は仕組みとして起きないようにする。AI（Claude）はマスタ作りにだけ関わり、アプリの実行中には使わない。
- 経緯:
  - grill-me で D1〜D16 を決めた。
  - その後 UI/UX 設計を加えた。
  - 4 体のサブエージェント（UI/UX デザイナー、シニアエンジニア、国語科講師、PM・法務）にレビューさせ、D17〜D21 を追加した。
- **進め方の要点**: 小さく出して広げる。v1 を 3〜5 人の生徒で 2 週間試し、その結果で調整してから全員に配る。

| D14 | 技術 | React + TypeScript + Tailwind CSS v4 + PWA（Vite でビルド、GitHub Actions で公開） |

| D16 | 画面の流れ | 1 問 1 画面で解き、最後にまとめて答え合わせする。自己採点は全部○から始め、書けなかった語だけ✕にする |
| D17 | 選んだ番号 | 答え合わせの各問の最初に、自分が選んだ番号を 1 回タップさせる。選択の正誤も記録する |
| D18 | 答えの書体 | 答え合わせの見本の漢字は教科書体（Klee One）にする。問題文は明朝体 |

| D21 | 試作運用 | 3〜5 人の生徒で 2 週間試し、成功の基準を確かめてから全員に配る |
| D23 | 別表記 | 正しい選択肢を選べていれば、別の正しい表記（例：換える／替える）で書いても正解とする。マスタの `alt` に登録し、答え合わせではカッコ書きで併記する |
| D24 | 同訓異字 | 「省みる（自らの過ちを）」と「顧みる（過去の出来事を）」のように、意味で書き分ける語は別々に登録する |
| D25 | 出題範囲の拡大 | 漢検 2 級まで（＝常用漢字の全 2136 字）を範囲にする。ただし、同音の選択式で出せない字（音読みがない字、同じ音の常用漢字が少なく 5 択を組めない字、自然な語が 1 つしかない字）は対象外とし、「出題しない字の一覧」に理由とともに記録する。増やす順番は、①過去問の語でマスタにないもの ②2 級配当漢字 ③残りの常用漢字。100〜200 語ずつ確認し、確認が済んだ分から公開する。語を足す前に、確認前の語を出題しない設定に切り替える（「試作版」の表示は残せる）。試作運用の間はマスタを公開し直さない。同音グループの形は「1 漢字 2 語・漢字は 3 の倍数（6・9・12…）」に広げ、偏りは simulate で確かめる（2026-10-16） |
| D22 | 訓読みの出題 | 訓読みの語（例：競う、帯びる、肩）も出題する。訓読み＝漢字の意味の理解につながり、漢文や新しい傾向の問題にも役立つため。訓読みの語は、その漢字の音読みの同音グループに入れる（競う → キョウ）。傍線はカタカナ部分だけに引き、送り仮名は線の外に置く（共通テストと同じ表記）。訓読みの語を設問にしたときは、選択肢を音読みの語だけで組む（訓読みどうしだと意味で選べてしまい、同音の字の練習にならないため。2026-10-20） |

## v1 と v2 以降の範囲
| v1（試作運用で使う版） | v2 以降 |
|---|---|

| 書き出し／読み込み、オフライン表示、`storage.persist()` | 検印カレンダー、試験日のカウントダウン、マスタ更新のお知らせ |
| 1 日の上限（新しい問題 3 セット、復習 30 語）、1 セットの問題数の設定 | `retired` と `redirects` による移行の処理（v1 では id を変えない運用で済ませる） |
| E2E は主な流れと、320px・375px の確認 | 複数の画面幅と横向きの網羅 |
- データの型（`Word` と保存データ）は、v2 の項目も入れられる形で最初から決めておく。v2 の項目は省略してよいものにし、v2 に進むときに保存データを移し替えなくて済むようにする。

## 出題ロジック
### 語彙データ
```ts
type Word = {
  id: string;          // "w0001"。一度振ったら変えない
  word: string;        // "沸騰"（重複は禁止）
  kana: string;        // "フットウ"
  key: string;         // "沸"：出題で問われる 1 字
  keyIndex: number;    // word の中で key が何字目か
  reading: string;     // "フツ"：key の音
  keyKana: string;     // "フッ"：kana の中での実際の表記（促音化・連濁に対応）
  sentence: string;    // "議論が{フットウ}する"（14 字以内）
  source: string | null;
  verified: boolean;
  keyGloss?: string;   // v2：字の意味（例：沸＝わく）
  confusable?: string[]; // v2：字形の似た字
  tier?: 'past' | 'standard' | 'advanced'; // v2：過去問の出題語／標準／発展
};
```
- マスタは `src/data/words.json` としてアプリに組み込む（import）。未確認の語はビルド時に除外する。
- 訓読みの出題（同訓異字）と、意味を問う形式は v1 では扱わない。
- 字体は常用漢字表（2010 年）に従う（剝・頰・𠮟・塡などはこの字体に統一する）。

### 問題の組み方（新しい問題）
1. 同じ音のグループを 1 つ選ぶ。未使用の語が多いグループほど選ばれやすくする。ただし、1 セットの中で同じ音は重ねない。
2. グループの中で漢字 K を選び、設問の語 T と、正解の選択肢（K を含む T 以外の語）を決める。
3. K 以外の漢字の語を 4 つ選び、誤りの選択肢にする。
4. **正解が 1 つかを検証する**: 正解の選択肢だけが K を含み、残り 4 つは T と同じ字を 1 字も含まないこと。
5. **周回の終わり**: 未使用の語だけで組めるグループがなくなったら、未使用が最も多いグループから組み、足りない枠は一番前に出た語で埋める。全語を使ったら次の周回に入る。
- 乱数は seed 付きの擬似乱数（mulberry32）を注入する。seed はセッションに保存する。

### 復習
- 書けなかった語 W を設問にし、選択肢は同じ音の語から組む。
- 選んだ番号が誤りだった場合は、自己採点にかかわらず、設問の語と、選んだ選択肢の語を復習に入れる。
- 時期を迎えた語が多いときは、期日の古い順に、1 日 30 語までとする。

### マスタの条件（`tools/validate.ts`）
- 各音のグループに 6 語以上、漢字 5 種以上。各漢字に 2 語以上。条件に足りないグループは、不自然な語を足して埋めず、出題から外す。
- `word` と `id` の重複を禁止する。常用漢字表にない字を禁止する。`reading` が常用漢字表の音にあること。
- `word[keyIndex] === key`、`kana` に `keyKana` が含まれること。例文は 14 字以内で、`{…}` が 1 か所だけ。

### 成り立つかの模擬（`tools/simulate.ts`）
- 実際のマスタを、複数の seed で数周させる。埋め合わせた割合と、語ごとの出題回数の偏りを出す。
- 埋め合わせの割合が 10% を超えたら、CI を失敗させる。
- v1 に必要な最小の語数（300〜400 語で足りるか）も、これで確かめる。

## 状態と保存
- Zustand の persist で、`settings`、`progress`、`session` の 3 つのキーに分けて保存する。それぞれ `version` と `migrate` を持つ。
- `progress` の語ごとの値: `{ lastSeq, review?: { stage, due, streak }, wrongCount, mastered }`
  - `lastSeq` は単調に増える出題番号。周回の判定と「一番前に出た語」の判定に使う。
  - 集計値だけを持つ。
- `session` は語の id で保存する。存在しない id があれば、そのセットは捨てる。途中で捨てたセットの語は「出題済み」として扱う。
- 日付:
  - 端末ローカルの `YYYY-MM-DD` で扱い、1 日の区切りは午前 4 時。
  - 時計が戻った場合に備え、`today = max(今日, 最後に使った日)` とする。
  - 現在時刻 `clock` と乱数 `rng` は、引数で注入する。
- iOS で 7 日開かないとデータが消える問題への対策:
  - `navigator.storage.persist()` を呼ぶ。
  - 最初のセットを終えたあとに、「ホーム画面に追加」を勧める（必須にはしない。初回で離れる生徒を出さないため）。
  - 最後の書き出しから 14 日たったら、書き出しを促す。
- 書き出しの JSON には `schemaVersion`、`masterVersion`、`exportedAt` を入れる。読み込みは上書きで行い、Zod で検証する。

## UI/UX 設計
### 利用シーンからの原則
- スマホを机に立て、横のノートに手書きする。
- 守ること:
  - 1 問がスクロールなしで 1 画面に収まる
  - 問題文は 22px 以上
  - 操作は親指の届く下側に置く
  - 解いている間は画面を消灯させない（Screen Wake Lock API）
- 番号は（ア）〜（オ）と ①〜⑤ にする。ノートには「ア-③ 沸騰」のように書いてもらう想定。

### ビジュアル言語：試験用紙×朱ペン
**色**（v1 はライトだけ。ダークの値は v2 のために決めておく）
| 役割 | ライト | ダーク（v2） |
|---|---|---|
| 背景 `--paper` | #F6F1E7 | #1A1916 |
| 面 `--sheet` | #FFFDF8 | #23211D |
| 文字 `--ink` | #1E1C19 | #ECE6DA |
| 補助文字 `--ink-sub` | #6A645A | #A39C8F |
| 区切り線 `--rule`（装飾のみ） | #DCD3C3 | #3A3731 |
| 部品の線 `--line`（3:1 以上） | #8F8676 | #77705F |
| 朱 `--shu` | #C23B22 | #EF7B61 |
| 朱ボタンの文字 `--on-shu` | #FFFFFF | #1A1916 |
| 朱の面 `--shu-wash` | #FBE9E4 | #3A231E |
- 朱は「採点」と「主要ボタン」だけに使う。○と✕は形でも区別できるようにする。
- 具体的な値は、実装時にコントラストを測って確定する（文字 4.5:1、文字以外の部品 3:1）。

**文字**（同梱し、マスタと UI の文言に使う字だけに絞る）
- 問題文・選択肢: BIZ UD明朝。22px（「大」の設定で 26px）
- 答え合わせの見本: Klee One。36px 以上
- ルビ: 14px
- UI: BIZ UDPゴシック。16px

**縦書きと傍線**
- 問題カードは縦書きが標準。カタカナには右側に傍線を引く。高さは `svh` で取る。
- 例文を 14 字以内に制限して、320px 幅でも 1 画面に収まるようにする。
- 設定で横書きにも切り替えられる。
- iOS Safari で傍線が右側に出ない場合は、`border` で代わりに描く。
- 答え合わせは常に横書きにし、ルビを添える。
- 問題の移動は、ボタンとキー操作だけで行う（スワイプは使わない）。

### 画面
```
ホーム ─┬─ 新しい問題 → 問題(ア)…(オ) → 答え合わせ(ア)…(オ) → 結果 → ホーム
        ├─ 復習       → （同じ流れ）
        └─ 設定・データ ／ このアプリについて（説明ページ）
```
1. **ホーム**
   - 今日の復習「12 語」
   - ［新しい問題を解く］（朱の塗り）と［復習する］（枠線）。上限に達したら「今日はここまで」と表示する。
   - 主な指標は「覚えた語数」（3 回続けて書けて、復習から外れた語）。周回の進み具合は小さく出す。
   - 途中のセットがあれば「続きから」を出す。その状態で新しく始めるときは確認する。
   - 書き出しを促すお知らせ
   - 初めて開いたときは、空のホームの上に、使い方を 3 行で示すカードを出す（閉じられる）。
2. **問題**
   - 上部に「新しい問題 2 / 5」と進み具合の点
   - 縦書きのカード（右端が設問、その左に ①〜⑤）
   - 下部に［前へ］［次へ］。5 問目では［答え合わせへ］
3. **答え合わせ**
   - 最初に「あなたが選んだ番号は？」を出し、①〜⑤ から 1 回タップさせる。そのあとで見本が開く。
   - 6 行を「番号／漢字（Klee One・ルビ付き）／書けた・書けなかった」の形で並べる。行の全体がタップ領域で、状態は文字で示す（`aria-pressed`）。
   - 正解の番号は朱の丸で囲む。自分が選んだ番号も示す。
   - **採点の基準**を常に表示する。「画の過不足や部品の取り違えは✕。とめ・はね・はらいの違いは○」（文化庁の字体・字形の指針に沿う）。詳しい例へのリンクも付ける。
   - 下部に［前へ］［次の問題］。最後は［採点を終える］
4. **結果**
   - 書けた語数 ／ 30、選択の正解数 ／ 5
   - 復習に入った語と、次の復習日。ここでも✕を付け直せる。
   - 全部書けたときは、朱の花丸を出す。
   - 結果は、そのままスクリーンショットで講師に提出できる見た目にする（試作運用で使う）。
   - ［ホームへ］［もう 1 セット］
   - 最初のセットのあとに、「ホーム画面に追加」を勧める（iOS では手順付き）。
5. **設定・データ**
   - 表示: 縦書き／横書き、文字の大きさ
   - 1 セットの問題数（3／5）
   - データ: 書き出し、読み込み（上書きの確認あり）、消去（「消去」と入力させて確認）
6. **このアプリについて**
   - データはこの端末にだけ保存し、外部に送らないこと
   - 大学入試センターとは関係がないこと
   - 無保証であること
   - フォントのライセンス表示
7. **特別な状態**
   - 復習がない: 「次の復習は○日」と表示する
   - 1 周したとき: 朱の花丸と「第 2 周へ」を出す
   - 最初の読み込みに失敗したとき: 再読み込みを促す

### アクセシビリティ
- タップ領域は 48px 以上にし、フォーカスリングを表示する。キーボードでは ←→ で問題を移動し、1〜5 で番号を選ぶ。
- 傍線部は、画面に出さない読み上げ用の文字で「傍線部、フットウ」と読ませる。
- ルビの `rt` は読み上げから外す。

### デザインの確認
- 実装の前に、主要 4 画面（ホーム／問題・縦書き／答え合わせ／結果）を、320px と 375px の動くモックとして Artifact で共有し、承認を得る。

## 進め方
1. **試作マスタ（約 150 語）と、generator・simulate・validate**: 出題が成り立つかを確かめ、v1 に必要な語数を確定する。5 択（1 問 6 語）の条件で確かめる
2. **足場**: Vite、React、TS、Tailwind、Biome、Vitest、PWA を整え、空のアプリで Pages への公開を一度通す。リポジトリの作成と push はユーザーの了承を得てから行う
3. **デザインモック**を Artifact で共有し、承認を得る（手順 4 と並行してよい）
4. **過去問の語集め → マスタを 300〜400 語に**: validate と simulate を通し、`review.html` でユーザーが確認する。共通テストの 4 択の過去問は、選択肢 4 語と設問の語を種として使い、同音グループで 5 択分に補う
5. **scheduler と store**をテストを書きながら作る
6. **画面**を作る: ホーム → 問題 → 答え合わせ → 結果 → 設定 → このアプリについて → 特別な状態
7. **フォントのサブセット化、ライセンス表示、運用手順書、v1 の公開**
8. **試作運用（2 週間）→ 調整 → 全員に配布 → v2 の項目に着手**

## 検証
- **Vitest と fast-check**
  - ランダムなマスタと採点の並びで、次が常に成り立つ。周回の中で語が重複しない／正解がちょうど 1 つ／誤りの選択肢が T と同じ字を含まない／1 セットの中で同じ音を重ねない／周回が必ず進む。
  - 復習: 「翌日 → 3 日後 → 7 日後 → 外れる」「途中で書けなければやり直し」「期日前に出た分は連続回数に数えない」「選んだ番号の誤りで設問の語と選んだ語が復習に入る」「1 日の上限」を確かめる。
  - 移行: 旧版の保存データを固定のテストデータにして確かめる。
- **`tools/simulate.ts`**: 埋め合わせの割合が 10% 以下（CI の合否条件）
- **`tools/validate.ts`**: エラーが 0 件
- **Playwright**（320×568、375×667）
  - `page.clock` で時刻を固定し、`addInitScript` で状態を注入する。
  - 新しい問題 → 番号選択 → ✕を 2 語 → 結果で 1 語を修正 → 日付を進めると復習に出る
  - フォントの読み込みを待ってから、1 問がスクロールなしで収まることを確かめる。
  - 書き出し → 消去 → 読み込みで状態が戻る
  - ビルド済みのアプリで、オフライン時の再読み込みを確かめる。
- **axe**: 重大な違反が 0 件。コントラストを測る。
- **実機**（iPhone Safari と Android Chrome）
  - ホーム画面に追加できる
  - 解いている間に画面が消えない
  - 縦書きの傍線が右側に出る
  - `storage.persist()` の結果を確かめる
- **試作運用**: 成功の基準 3 つで判定する。
